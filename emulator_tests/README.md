# Emulator tests

End-to-end checks of the Cloud Functions and the Firestore and Storage rules, run against the Firebase emulators with a demo project (no real data or services are touched). Vision is replaced by a fake result stored on each test photo.

```sh
(cd functions && npm run build)
firebase emulators:exec --only auth,functions,firestore,storage --project demo-codami \
  "node emulator_tests/moderation.cjs && node emulator_tests/points_emergency.cjs && node emulator_tests/feedback_notes.cjs && node emulator_tests/feedback_asks.cjs && node emulator_tests/petitions.cjs && node emulator_tests/app_version.cjs && node emulator_tests/shop.cjs && node emulator_tests/phase4.cjs && node emulator_tests/invites.cjs && node emulator_tests/scanner.cjs && node emulator_tests/heat.cjs && node emulator_tests/sitting.cjs && node emulator_tests/schedule.cjs && node emulator_tests/sharing.cjs && node emulator_tests/share_reminders.cjs"
```

The Places key is a secret: create `functions/.secret.local` with `PLACES_API_KEY=emulator-placeholder` (not committed), or the emulator warns that it can't reach Secret Manager. `invites.cjs` clears invites left by the earlier scripts before its own checks.

Each script prints one PASS or FAIL line per check and exits with an error if anything fails.

- `moderation.cjs`: AI photo moderation (clear, review, blocked, injured animals, quarantine, approve, remove, rules)
- `points_emergency.cjs`: daily rewards, streaks, invite codes, referral checks and admin review, emergencies, nearby alerts, contacts and their rules
- `feedback_notes.cjs`: feedback points (once per account), who can read feedback, the feedback and review settings, "What's new" notes and their rules, feedback removed with the account
- `feedback_asks.cjs`: internal feedback: type, part of the app, optional stars, screenshot (own folder only, images up to 5 MB, only the team opens it), five a day at most; the team's inbox (status and private note through the server only, users can't change them, a thank-you once per feedback); question settings admin only (uses "to" not below "from", pause 3 to 90 days, 1 to 20 questions); the user's own question history and "don't ask again"; feedback and screenshots removed with the account. When to ask is covered by `test/feedback_rules_test.dart`
- `petitions.cjs`: petitions: only admins write, users see only published ones, link and field checks, verification checks needed to approve or publish, image upload rules
- `app_version.cjs`: app update settings: readable before sign-in, only admins write, version and App Store ID checks, unknown fields refused
- `shop.cjs`: shop: users only read the catalogue while the shop is on, hidden items stay hidden, suppliers are admin only, only admins write, product, category, brand and supplier field checks, photo and logo upload rules
- `phase4.cjs`: places to walk and donation settings (only admins write, field checks, payments can't be marked ready from the app), the walk search functions (off for users, input checks, sign-in, daily limit before Google is called)
- `invites.cjs`: invite tracking: QR scans and link opens from the invite page (once a day per visitor, unknown codes ignored, no IP kept, counters hidden from users), the admin counts per user (active, inactive, waiting, still using, friends list), the ranking with periods and sorting, and open counts removed with the account
- `scanner.cjs`: breed scanner: the model list for admins only (the usual models in the emulator), only admins change the settings (daily scans 1 to 100, Gemini model names only), off for users but open to admins, sign-in, photo checks (real image types only), the cleaned answer (most likely breed first, alternatives with %, facts), the daily limit and the next day, counters hidden from users and holding no photos, the counter removed with the account. Gemini isn't called: the emulator answers with a fixed Labrador result
- `heat.cjs`: heat calendar: only admins change the settings, heats and reminders only for the owner's own pets (nobody else reads them, not even admins), date, end-after-start, notes and field checks, edits can't move a heat or change its creation time, reminders only 1/3/7/14 days before, turning off a missing reminder works, everything removed with the account. The daily reminder sweep is covered by `functions/src/heat.test.ts`
- `sitting.cjs`: pet sitting: settings admin only; sitter profiles (own only, no self-written rating or counts, hidden by staff); requests (open only, no address, owner edits, no booking by hand); offers (sitter profile needed, one per sitter, not on your own request, read by owner and sitter only, blocked users can't offer); booking by the server (others declined, no double booking); confirmation by both sides after the start; verified reviews only after both confirmed, one per service, not by the sitter, new accounts wait, written only by the server, staff hiding updates the rating; private chats between two members (no outsiders, not even admins, blocked users can't write); reports; everything removed with the account
- `schedule.cjs`: personal schedule: only admins switch it on or off; events only in your own name and readable only by you (not even admins, not by listing either); type, date, time, repeat, reminder count (2 at most, 60 planned at most) and text length checks; done and skipped days; an event can't be given to someone else or have its creation time changed; everything removed with the account. The reminder sweep is covered by `functions/src/schedule.test.ts`
- `sharing.cjs`: social sharing: only admins switch the pop-up; shares counted only by the server (signed in, known apps only, not for hidden or missing reports); the owner and admins read a report's numbers, other users don't, nobody writes them; daily totals for admins only; the public report page (in the visitor's or sharer's language, link preview tags, no phone, email, owner name or position, Open in CodaMi link, visits counted by source but not link previews, hidden and deleted reports "no longer available", resolved ones celebrate); numbers removed with the account
- `share_reminders.cjs`: share reminders: only admins change the settings (first after 1 to 60 days, every 3 to 60 days, 1 to 52 in total); the first visit plans the first reminder 3 days after sign-up and later visits keep the plan; users read only their own plan and nobody writes it; opened and shared counted for admins; sharing CodaMi or a report pauses the reminders; the Notifications switch (unknown types refused); test reminders for admins only; the plan removed with the account. The evening sweep is covered by `functions/src/shareReminders.test.ts`
